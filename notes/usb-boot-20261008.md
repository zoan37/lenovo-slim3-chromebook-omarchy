# First USB stick, 2026-10-08

Built from ChromeOS developer mode over the bridge with [`scripts/build-usb.sh`](../scripts/build-usb.sh)
(SanDisk 3.2Gen1, 28.6 GB, `/dev/sdb`).

- `crossystem dev_boot_usb=1` works with hardware write protect on; it prints two harmless
  `linux_mtd_wp_write_cfg: Failed to disable write-protection` lines first.
- Layout: GPT, part 1 `KERN-A` (32 MB, ChromeOS kernel, priority 10 / tries 5 / successful 1), part 2 `ROOT`
  (ext4, label `ALARM`).
- Rootfs: Arch Linux ARM aarch64 tarball (signature checked against the Arch Linux ARM Build System key
  `68B3537F39A313B3E574D06777193F152BDBE6A6`), 2.1 GB unpacked. ChromeOS `/lib/modules/6.6.143-…` copied to
  `/usr/lib/modules/`, ChromeOS `/lib/firmware` to `/usr/lib/firmware/updates/` (searched first by the kernel,
  and owned by no package).
- The tarball has no Wi-Fi tools, so `wpa_supplicant` was installed by chrooting into the stick from ChromeOS
  (same architecture, so `pacman` runs directly). Wi-Fi credentials come from ChromeOS's saved network in
  `/var/cache/shill/default.profile` (`Name=`, `WiFi.Passphrase=`), written straight to
  `/etc/wpa_supplicant/wpa_supplicant-wlan0.conf` and never printed. `net.ifnames=0` keeps the name `wlan0`.
- Enabled: `systemd-networkd` (DHCP on `wlan*`), `wpa_supplicant@wlan0`, `systemd-resolved`,
  `systemd-timesyncd`, `sshd` (laptop key in root's and alarm's `authorized_keys`), `cbridge.service` (the
  bridge agent, so the booted system can be driven with no screen). Persistent journal (`/var/log/journal`).
- Kernel: KERN-A from the internal disk, repacked with `futility vbutil_kernel --repack` and the devkeys
  (`kernel.keyblock`, `kernel_data_key.vbprivk`; data key sha1 `d6170aa4…` instead of Google's `049b9a52…`).
  Command line:
  ```
  console= loglevel=7 init=/sbin/init root=PARTUUID=%U/PARTNROFF=1 rootwait rw noinitrd net.ifnames=0
  lsm=capability,landlock,yama,bpf cpuidle.governor=teo irqchip.gicv3_pseudo_nmi=1
  ```
  `lsm=` drops LoadPin (would pin module/firmware loading to the verity root), the chromiumos LSM (blocks
  symlinked mount paths) and SELinux (no policy in Arch).

## Gotchas hit while building

- The chroot's `pacman-key` leaves a `gpg-agent` running inside, so `umount $M/dev` fails with "target is busy".
  The script now runs `gpgconf --kill all` in the chroot and kills anything whose `/proc/*/root` is the stick.
- Re-running only the tail of the script deleted `/etc/resolv.conf` (the restore step ran twice). Fixed by
  restoring only when the `.orig` exists; the stick got `resolv.conf -> /run/systemd/resolve/stub-resolv.conf`.

## First boot result

Booted on the first try from the developer screen's **Boot from external disk**. Within a minute the bridge agent
connected; `systemctl is-system-running` = `running`, `systemctl --failed` empty, `wlan0` got DHCP, SSH as root
with the laptop key works. Screen stays on the last firmware image (no VT/fbcon).

Input devices: `gpio-keys`, `Elan Touchpad`, `cros_ec` (keyboard), `cros_ec_buttons`, `tc3408 1DA0:3018`
(touchscreen), `mt8189_1019_rt5682s` headset/DP/HDMI jacks. Sound card is the RT5682S variant, not NAU8825.
48 modules loaded. Battery via `sbs-battery`.

Harmless or expected boot noise: `Failed to find module 'autofs4'` (no `CONFIG_AUTOFS_FS`, systemd copes),
`unable to open an initial console` (no VT), `clk-mt8189-mmsys … -22`, `mali … Failed to find OPP for frequency
1099999634`, `sx9324 … -ENXIO` (SAR proximity sensor not fitted), device-link warnings.
